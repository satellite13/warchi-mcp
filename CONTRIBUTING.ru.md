# Вклад в warchi-mcp

Спасибо за интерес к проекту.

## Требования для разработки

- JDK 24/25
- Работающий arepos-server (для smoke-проверок против реального API)
- Опционально: Docker

## Локальный запуск

```bash
export AREPOS_BASE_URL=http://localhost:8080
./gradlew build
./gradlew test
```

Запуск приложения:

```bash
./gradlew bootRun
```

## Ветки и Pull Request

1. Создайте ветку от `master`
2. Делайте коммиты атомарными и сфокусированными
3. Добавляйте/обновляйте тесты при изменении поведения
4. Открывайте PR с описанием контекста и плана проверки

## Рекомендации по коммитам

- Используйте чёткие заголовки в повелительном наклонении
- Поясняйте *зачем* сделано изменение, а не только *что* изменено
- По возможности отделяйте рефакторинг от функциональных изменений

## Что запускать перед PR

```bash
./gradlew build
./gradlew test
```

При изменении контрактов MCP tools обновляйте `docs/tools.md` и `docs/tools.ru.md`.

При изменении auth — `docs/auth.md` и `docs/auth.ru.md`.

## Чеклист Pull Request

- [ ] Код собирается локально
- [ ] Тесты проходят локально
- [ ] Есть тесты на новое поведение
- [ ] Документация обновлена при необходимости
- [ ] В репозиторий не попали секреты, API-ключи и персональные данные

## Как сообщать о проблемах

Укажите:

- ожидаемое поведение
- фактическое поведение
- шаги воспроизведения
- версии MCP-клиента / arepos при необходимости
- логи или stack trace (без API-ключей и JWT)
